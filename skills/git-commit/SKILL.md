# Git 智能规范化提交流程 (Git Commit)

深度分析当前工作区与暂存区的改动，排查安全与敏感隐患，提炼规范提交信息，并支持多模块分步交互式弹窗确认提交。

## 执行流程

### 1. 环境与工作区状态初检
- 执行 `git status -s` 与 `git status`。
- **空工作区拦截**：若没有任何修改或新增文件，直接提示“工作区干净，无需提交”并结束流程。
- **已有暂存区识别**：若当前已有部分文件被 `git add` 暂存，优先调用 `ask_user_question` 确认是“仅提交已暂存文件”还是“重新规划完整提交”。
- **敏感与临时文件防护**：严格检查未跟踪文件（`??`）中是否包含 `.env`、密钥证书（如 `*.pem`、`*.key`、`id_rsa`）、本地调试临时日志、大型二进制或系统生成垃圾文件（如 `.DS_Store`、`Thumbs.db`）。发现敏感或无关文件必须予以警告并排除在提交之外。

### 2. 改动分析与模块聚类
- 结合 `git diff`（工作区）与 `git diff --cached`（暂存区）分析变更内容及上下文。若用户输入中提供了附加说明或核心意图，优先采纳。
- **跨模块公共文件处理**：若 `pubspec.yaml`、`package.json`、公共路由或全局配置等跨模块文件同时包含多处改动，优先将其作为独立的基础依赖/配置模块，或合理归并到主改动模块。

### 3. 单一模块提交流程
若所有变更属于单一业务、功能或缺陷修复单元：
1. 提炼符合 **Conventional Commits** 规范的精准提交信息（格式：`<type>(<scope>): <subject>`，类型包括 `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `perf`, `style` 等）。
2. 调用 `ask_user_question` 弹出选项确认：
   - 选项提供推荐提交说明（附带 `(Recommended)`）及微调选项。
3. 确认后精准 `git add <files>` 并执行 `git commit -m "..."`。

### 4. 多模块改动拆分流程（逐个交互确认）
若变更涉及多个互不相关的模块或职责，**严禁一揽子全部提交**！
1. 按模块依赖与业务重要性划分文件清单。
2. **逐个模块**调用 `ask_user_question` 向用户弹窗确认：
   - 选项应包含：
     - 提交该模块（附带该模块的推荐提交说明）
     - 跳过该模块暂不提交
     - 一键合并后续剩余模块
3. 确认后精准 `git add <files>` 并提交该模块。
4. 依序推进，直至所有待提交模块处理完毕。

### 5. 安全与质量底线
- **冲突标记拦截**：严格拦截 Git 冲突标记（如 `<<<<<<`、`======`、`>>>>>>`），发现立即中止并提醒排查。
- **禁止私自 Push**：在没有明确的用户指令前，严禁自动执行 `git push`。
- **结果回显**：提交完成后输出 `git log -n 1 --stat` 汇总展示本次提交结果。
