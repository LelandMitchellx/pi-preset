# 技术调查与使用指南 (Investigate Tech)

当用户发送一个或多个链接（如 GitHub 仓库、产品官网、技术文档、博客文章），或者提出技术/工具/框架相关的疑问时，按以下规范执行调查并结构化输出。

## 执行流程

1. **信息获取**：
   - **若是链接**：优先使用环境可用检索工具（如联网检索、curl、Git 克隆或直接读取）获取网页/仓库正文内容。如果是 GitHub 仓库或文档站点，提取核心 README、特性列表、快速上手（Quick Start）和安装运行指南。
   - **若是疑问/技术名词**：检索该技术/工具的官方文档、权威百科或代码仓库获取最佳实践。

2. **信息提炼与分析**：
   聚焦于两大核心问题，过滤无关的宣传噱头或杂质：
   - 它解决了什么问题？适合什么场景？核心价值是什么？（**有什么用**）
   - 怎么装？怎么配？最基础/最典型的代码或命令怎么写？（**如何使用**）

3. **输出格式**：
   严格按照以下两大部分进行结构化输出，保持清晰、简练、实用：

```markdown
## 一、有什么用

- **核心定位**：一句话概括它是什么、面向什么人群/场景。
- **主要功能与价值**：
  - 功能点 1：解决了什么痛点 / 带来了什么提升。
  - 功能点 2：...
- **适用场景**：在什么情况下建议使用（或不建议使用）。

---

## 二、如何使用

- **前置准备 / 安装**：
  - 依赖环境、安装命令（如 npm / pip / brew / docker 等）。
- **快速上手 / 配置**：
  - 核心配置项或环境变量说明。
- **示例代码 / 典型命令**：
  - 给出最小可用示例（Minimal Working Example / Quick Start）。
- **注意事项 / 常见坑点**（可选）：
  - 简要提醒常见问题或最佳实践。
```

## 注意事项
- 语言统一使用简体中文，内容准确客观，代码块标注对应语言。
- 避免冗长无效的叙述，代码示例力求可复制运行。
